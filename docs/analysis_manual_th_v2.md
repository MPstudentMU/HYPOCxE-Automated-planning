## 1. ภาพรวมของแพลตฟอร์ม (Platform Overview)

แพลตฟอร์มนี้ถูกพัฒนาขึ้นเพื่อประเมินประสิทธิภาพของระบบสร้างแผนการรักษาอัตโนมัติ (Automated VMAT Planning) สำหรับผู้ป่วยมะเร็งปากมดลูกและมะเร็งเยื่อบุโพรงมดลูก โดยเปรียบเทียบกับแผนการรักษาที่สร้างโดยนักฟิสิกส์การแพทย์ (Manual Planning) ระบบประมวลผลข้อมูลจากไฟล์ส่งออกของระบบวางแผนการรักษา (TPS Export) เช่น RayStation เพื่อวิเคราะห์ตัวชี้วัดหลัก 3 ด้าน ได้แก่ อัตราการผ่านเกณฑ์ทางคลินิก ประสิทธิภาพด้านเวลา และคุณภาพของแผนการรักษาเชิงลึกร่วมกับความสม่ำเสมอของผลลัพธ์

### 1.1 ความเชื่อมโยงกับวัตถุประสงค์การวิจัย

| วัตถุประสงค์ | ตัวชี้วัดในแพลตฟอร์ม | โมดูล |
|---|---|---|
| **วัตถุประสงค์หลัก:** สร้างกระบวนการวางแผนที่มีคุณภาพเป็นที่ยอมรับทางคลินิก และลดระยะเวลาวางแผนรวม (Total Planning Time) | %Pass Rate (Straight-pass และหลังการปรับแก้) และ %Time Efficiency | Module 1, Module 2 |
| **วัตถุประสงค์รอง:** ลดความแปรปรวนของคุณภาพแผนอันเนื่องจากทักษะและประสบการณ์ของผู้วางแผน (Inter-planner Variability) | Weighted Quality Score, Quality Index, SD/CV และการทดสอบความแปรปรวนแบบจับคู่ | Module 3 |

### 1.2 กลุ่มแผนการรักษาที่นำมาเปรียบเทียบ

| กลุ่มแผน | นิยาม | บทบาทในการวิเคราะห์ |
|---|---|---|
| **Manual** | แผนที่สร้างโดยนักฟิสิกส์การแพทย์ตามกระบวนการมาตรฐาน | กลุ่มอ้างอิง (Reference) |
| **Auto** | แผนที่สร้างจากสคริปต์อัตโนมัติ โดยไม่มีการปรับแก้ด้วยมือ | ใช้ประเมิน Straight-pass Rate |
| **Auto+Manual** | แผน Auto ที่ผ่านการปรับแก้เพิ่มเติมด้วยมือ | ใช้ประเมิน Pass Rate หลังการปรับแก้ และเวลาของกระบวนการอัตโนมัติจริง |

### 1.3 สถาปัตยกรรมและลำดับการประมวลผล

```
แถบด้านข้าง (Sidebar): HN · Pt no. · Dose prescription · Nodal SIB · Planning time · Excel
        │
        ▼
engine/parser.py  ── ตรวจรูปแบบไฟล์ · ระบุชนิดแผน/ผู้ป่วย · ตรวจ HN · ทำความสะอาดข้อมูล
        │
        ▼
engine/storage.py ── บันทึกลงฐานข้อมูล SQLite (patients · planning_times · clinical_goals · upload_log)
        │                                     ▲ ข้อมูลดิบถูกเก็บก่อนการเติมข้อมูล Straight-pass
        ▼
Straight-Pass Exception Rule ── เติมข้อมูล Auto+Manual ณ เวลาวิเคราะห์
        │
        ▼
engine/analysis.py + engine/scoring.py ── Module 1 · Module 2 · Module 3 · Critical Alert
        │
        ▼
engine/charts.py (Plotly) ──► Dashboard 5 แท็บ: Summary │ M1 │ M2 │ M3 │ Registry & Export
```

แดชบอร์ดคำนวณผลใหม่ทุกครั้งที่มีการโต้ตอบ (re-run) จากข้อมูลทั้งหมดในฐานข้อมูล ผลลัพธ์จึงสะท้อนสถานะของกลุ่มตัวอย่างทั้งหมด ณ ขณะนั้นแบบทันที (real-time) เมื่อมีการเพิ่มผู้ป่วยรายใหม่

## 2. กระบวนการนำเข้าและจัดการข้อมูล (Data Input & Pre-processing)

### 2.1 ข้อมูลที่บันทึกผ่านแบบฟอร์ม

| ช่องข้อมูล | ชนิด | การประมวลผล |
|---|---|---|
| HN | ข้อความ | ใช้ตรวจสอบความสอดคล้องกับชื่อไฟล์ (ข้อ 2.3) และแสดงผลแบบปิดบังในหน้าทะเบียน |
| Pt no. (จำเป็น) | ข้อความ | ปรับให้อยู่ในรูปแบบมาตรฐาน เช่น `7`, `pt 7`, `PT07` → `Pt7` |
| Dose prescription | ตัวเลือก | `45 Gy / 25 fx` หรือ `44 Gy / 20 fx` ใช้กำหนดระดับรังสี 95% Rx สำหรับ Critical Alert |
| Nodal SIB boost | ช่องทำเครื่องหมาย | บันทึกเป็น 0/1 |
| Planning time (Manual / Auto / Auto+M) | ตัวเลข (นาที) | เวลาของ Auto+Manual บันทึกเป็น **เวลาสะสม** (เวลาสร้างแผนอัตโนมัติ + เวลาปรับแก้) |
| Clinical goal Excel | ไฟล์ .xlsx (1–3 ไฟล์ หรือไฟล์รวม) | ประมวลผลตามข้อ 2.2 |

### 2.2 Data Upload & Validation

ระบบรองรับไฟล์ Excel ที่มีข้อมูล Clinical Goals และค่า DVH ที่ได้จากแผนการรักษา โดยตรวจจับรูปแบบไฟล์โดยอัตโนมัติ 2 รูปแบบ

**รูปแบบ A – RayStation Export (หนึ่งแถวต่อหนึ่ง Clinical Goal)**

| คอลัมน์ | ความหมาย | ตัวอย่าง |
|---|---|---|
| `Pt` | ลำดับผู้ป่วย (ถ้ามี) | 3 |
| `Priority` | ระดับความสำคัญของเกณฑ์ (1–3) | 1 |
| `ROI` | ชื่อโครงสร้างตามที่ส่งออกจาก TPS | `PTV 45`, `Kidney_L` |
| `Goal` | ข้อความเกณฑ์ | `V4000cGy <= 75.0%` |
| `GoalType` | ชนิดตัวชี้วัด | `DoseAtVolume`, `VolumeAtDose`, `AverageDose`, `AbsoluteVolumeAtDose`, `DoseAtAbsoluteVolume` |
| `Criteria` | ทิศทางของเกณฑ์ | `AtMost` (ไม่เกิน) หรือ `AtLeast` (ไม่น้อยกว่า) |
| `AcceptanceLevel` | ค่าเป้าหมาย (cGy, สัดส่วน 0–1 หรือ cc) | 0.75 |
| `ParameterValue` | ระดับรังสีหรือปริมาตรที่อ้างอิง | 4000 |
| `AchievedValue` | ค่าที่แผนทำได้จริง | 0.62 |
| `Status` | ผลการประเมินจาก TPS | `PASS` / `FAIL` |
| `Plan` | ชนิดแผน (ถ้ามี) | `Auto+Manual` |

**รูปแบบ B – Combined Workbook (หนึ่งแถวต่อหนึ่งเกณฑ์ และแยกคอลัมน์ตามชนิดแผน)** ประกอบด้วยคอลัมน์เกณฑ์ข้างต้นร่วมกับ `Achieved_Manual`, `Achieved_Auto`, `Achieved_AutoManual` (และ `Status_<แผน>` ถ้ามี) พร้อมชีต `PlanningTime` (ไม่บังคับ) ระบบจะแปลงข้อมูลเป็นรูปแบบ A ก่อนประมวลผล

**ลำดับการระบุตัวตนของข้อมูล**

| ข้อมูล | ลำดับแหล่งที่ใช้ระบุ |
|---|---|
| ชนิดแผน | คอลัมน์ `Plan` → ชื่อชีต → ชื่อไฟล์ (เช่น `_AutoManual`, `_Manual`, `_Auto`) |
| ผู้ป่วย | Pt no. จากแบบฟอร์ม → คอลัมน์ `Pt` → ตัวเลขนำหน้าชื่อไฟล์ (เช่น `3clinical_goals_…` → `Pt3`) |

หากคอลัมน์ `Pt` ในไฟล์ที่มีแผนเพียงชนิดเดียวมีค่ามากกว่าหนึ่งค่า (ลักษณะของการลากเติมเซลล์โดยไม่ตั้งใจ) ระบบจะใช้หมายเลขจากชื่อไฟล์แทนและบันทึกคำเตือนใน Data-quality log

### 2.3 การตรวจสอบ HN กับชื่อไฟล์ (Patient Identity Safeguard)

ไฟล์ส่งออกจาก RayStation มักมี HN อยู่ในชื่อไฟล์ ระบบจึงสกัดตัวเลข 7–9 หลักจากชื่อไฟล์และดำเนินการดังนี้

| สถานการณ์ | การดำเนินการของระบบ |
|---|---|
| HN ที่กรอก **ตรงกับ** HN ในชื่อไฟล์ | นำเข้าไฟล์ตามปกติ |
| HN ที่กรอก **ไม่ตรงกับ** HN ในชื่อไฟล์ | **ไม่นำเข้าไฟล์นั้น** และแสดงข้อความแจ้งข้อผิดพลาด เพื่อป้องกันการนำเข้าข้อมูลผิดผู้ป่วย |
| ไม่ได้กรอก HN และทุกไฟล์มี HN เดียวกัน | ใช้ HN จากชื่อไฟล์โดยอัตโนมัติ |
| นำเข้าแบบกลุ่ม (Batch) แล้วพบผู้ป่วยหนึ่งรายมีหลาย HN | บันทึกคำเตือนให้ผู้วิจัยตรวจสอบ |

ในหน้าทะเบียนผู้ป่วย HN จะแสดงแบบปิดบัง (เช่น `•••• 7146`) โดยค่าเริ่มต้น และไม่ถูกเขียนลงไฟล์ส่งออกผลการวิเคราะห์ ฐานข้อมูลควรจัดเก็บภายในเครือข่ายของโรงพยาบาลเท่านั้น

### 2.4 การทำความสะอาดและจัดมาตรฐานข้อมูล (Data Cleaning & Harmonisation)

| ประเด็นข้อมูล | กฎการจัดการ | เหตุผลเชิงวิเคราะห์ |
|---|---|---|
| แถวซ้ำจากการส่งออกซ้ำ | ลบแถวที่มีผู้ป่วย แผน Priority ROI Goal AcceptanceLevel และ ParameterValue ซ้ำกัน | ป้องกันการนับเกณฑ์ซ้ำซึ่งทำให้ %Pass Rate และคะแนนคลาดเคลื่อน |
| Priority = 2147483647 | ถือเป็น "ไม่ได้กำหนด Priority" (ค่าเริ่มต้นของ RayStation) และคัดออกจากการให้คะแนน | ไม่มีตัวคูณตามโปรโตคอลรองรับ |
| `AchievedValue` ว่าง | ระบุเป็น **Non-evaluable** คัดออกจากการให้คะแนน และคัดออกจาก %Pass Rate โดยค่าเริ่มต้น | เป็นข้อจำกัดการคำนวณของ TPS (มักเกิดกับเกณฑ์หน่วย cc) มิใช่คุณภาพของแผน |
| ไม่มีคอลัมน์ `Status` | คำนวณจาก `AchievedValue` เทียบ `AcceptanceLevel` ตามทิศทาง `Criteria` | รองรับไฟล์รูปแบบ B |
| ชื่อโครงสร้างไม่สม่ำเสมอ | แปลงเป็นชื่อมาตรฐาน (ตารางด้านล่าง) | ให้เปรียบเทียบข้ามผู้ป่วยได้ใน Boxplot และ Radar Chart |
| รายการเกณฑ์ต่างกันระหว่างแผน | สร้างรหัสเกณฑ์ (`GoalKey`) และมีตัวเลือก **Matched goals only** | เปรียบเทียบบนชุดเกณฑ์เดียวกันได้เมื่อต้องการความเท่าเทียมเชิงระเบียบวิธี |

**ตัวเลือกการวิเคราะห์ (Settings)**

| ตัวเลือก | ค่าเริ่มต้น | ผลต่อการวิเคราะห์ |
|---|---|---|
| Exclude non-evaluable goals | เปิด | ตัดเกณฑ์ที่ TPS คำนวณค่าไม่ได้ออกจากตัวหาร %Pass Rate |

### 2.5 Straight-Pass Exception Rule

ลอจิกสำคัญในการจัดการข้อมูล: หากแผน Auto มีคุณภาพผ่านเกณฑ์โดยไม่ต้องปรับแก้ (Straight-pass) ข้อมูลในฝั่ง Auto+Manual จะว่างเปล่า ระบบจะคัดลอกข้อมูลเวลาและค่า DVH จากแผน Auto ไปใส่ใน Auto+Manual โดยอัตโนมัติ เพื่อให้ค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐาน (SD) ของกลุ่ม Auto+Manual คำนวณจากกลุ่มตัวอย่างครบทุกราย

**เงื่อนไขการทำงาน**

1. ผู้ป่วยมีข้อมูลแผน Auto และ
2. ไม่มีข้อมูลแผน Auto+Manual **หรือ** ทุกแถวของ Auto+Manual มี `AchievedValue` ว่าง

**การดำเนินการ**

| ขั้นตอน | รายละเอียด |
|---|---|
| คัดลอกค่า DVH | ทำสำเนาทุกเกณฑ์ของแผน Auto เป็นแผน Auto+Manual และกำกับสถานะ `ImputedFromAuto = True` |
| คัดลอกเวลา | หากเวลา Auto+Manual ว่าง ให้ใช้เวลาของ Auto |
| การแสดงผล | แสดงรายชื่อผู้ป่วย Straight-pass ในแท็บ Summary และในค่า hover ของกราฟ |
| การจัดเก็บ | ข้อมูลดิบในฐานข้อมูล **ไม่ถูกแก้ไข** การเติมข้อมูลเกิดขึ้น ณ เวลาวิเคราะห์ หากภายหลังมีการอัปโหลดแผน Auto+Manual จริง ระบบจะใช้ข้อมูลจริงแทนโดยอัตโนมัติ |

> **ข้อพิจารณาทางสถิติ** ผู้ป่วยกลุ่ม Straight-pass จะมีผลต่างระหว่าง Auto กับ Auto+Manual เท่ากับศูนย์ ซึ่งเป็นผลต่างที่มีความหมายทางคลินิก (ไม่ต้องปรับแก้) แต่ส่งผลต่อการทดสอบแบบจับคู่ระหว่าง Auto กับ Auto+Manual (เช่น การจัดการค่าศูนย์ใน Wilcoxon signed-rank test) จึงควรรายงานจำนวนผู้ป่วย Straight-pass ควบคู่กับผลสถิติเสมอ

## 3. กระบวนการวิเคราะห์ข้อมูลและการแสดงผล (Analysis Modules)

### Module 1: อัตราการผ่านเกณฑ์คลินิก (Clinical Acceptability Rate)

#### กระบวนการวิเคราะห์ (Analysis Logic)

ประเมินแผนการรักษาแต่ละแผนเทียบกับเกณฑ์มาตรฐานของสถาบัน (Institutional Clinical Goals) รายผู้ป่วยและรายชนิดแผน โดยคำนวณจากสมการ

```
% Pass Rate = (จำนวน Goal ที่ผ่านเกณฑ์ / จำนวน Goal ทั้งหมด) × 100
```

ตัวหารคือจำนวนเกณฑ์ที่เหลือหลังผ่านตัวกรองในข้อ 2.4 สถานะผ่านเกณฑ์ใช้ค่า `Status` จาก TPS เป็นหลัก

| ตัวชี้วัด | นิยามในแพลตฟอร์ม | เป้าหมาย |
|---|---|---|
| **Straight-pass Rate** | %Pass Rate ของแผน **Auto** (ไม่มีการปรับแก้ด้วยมือ) | ≥ 50% |
| **Pass Rate after Manual Modification** | %Pass Rate ของแผน **Auto+Manual** (เวลาปรับแก้ถูกรวมใน Total Planning Time) | ≥ 70% |
| Priority-1 Pass Rate | %Pass Rate เฉพาะเกณฑ์ Priority 1 | ใช้ประกอบการตีความ |
| Target met | จำนวนผู้ป่วยที่แผนผ่านเป้าหมาย / จำนวนผู้ป่วยทั้งหมด | รายงานรายกลุ่มแผน |

สถิติเชิงพรรณนาระดับกลุ่มตัวอย่าง ได้แก่ n, Mean, SD, Median, Min, Max และสัมประสิทธิ์การแปรผัน `CV (%) = SD / |Mean| × 100`

#### รูปแบบการแสดงผล (Visualization)

| องค์ประกอบ | รายละเอียด |
|---|---|
| **Data Table** | ตารางสรุป %Pass Rate รายผู้ป่วย เปรียบเทียบ 3 แผน (Manual, Auto, Auto+Manual) พร้อมตารางสถิติระดับกลุ่มและคอลัมน์ Target met |
| **Grouped Bar Chart** | กราฟแท่งจัดกลุ่มรายผู้ป่วย แสดงร้อยละการผ่านเกณฑ์ของทั้ง 3 แผน โดยมี **Threshold Lines** แบบเส้นประกำกับไว้ที่ **50%** (สีน้ำเงิน สำหรับแผน Auto) และ **70%** (สีเขียวอมฟ้า สำหรับแผน Auto+Manual) เพื่อให้ผู้วิจัยประเมินสถานะได้ทันที |
| **Cohort Mean ± SD Chart** | กราฟแท่งค่าเฉลี่ยพร้อม Error bar (SD) รายชนิดแผน และเส้นเป้าหมายเดียวกัน |
| ตารางรายละเอียด | จำนวนเกณฑ์ทั้งหมด จำนวนที่ผ่าน และ Priority-1 Pass Rate (ใน Expander) |

รหัสสีของแผนที่ใช้ตลอดทั้งแพลตฟอร์ม: Manual = เทา (`#8A94A6`), Auto = น้ำเงินการแพทย์ (`#1F5FAE`), Auto+Manual = เขียวอมฟ้า (`#14A38B`)

### Module 2: ประสิทธิภาพด้านเวลา (Time Efficiency)

#### กระบวนการวิเคราะห์ (Analysis Logic)

บันทึกระยะเวลาวางแผน (หน่วยนาที) โดยเริ่มนับตั้งแต่การนำเข้าภาพ CT และโครงสร้าง (Import) จนถึงการคำนวณปริมาณรังสีขั้นสุดท้าย (Final dose calculation) ที่แผนพร้อมส่งตรวจสอบ แล้วคำนวณร้อยละการลดเวลาเทียบกับแผน Manual ของผู้ป่วยรายเดียวกัน

```
% Time Efficiency (Auto)        = [(เวลา Manual − เวลา Auto) / เวลา Manual] × 100
% Time Efficiency (Auto+Manual) = [(เวลา Manual − เวลา Auto+Manual) / เวลา Manual] × 100
```

- **Efficiency ของ Auto** เป็นตัวชี้วัดตามนิยามของโปรโตคอล สะท้อนศักยภาพสูงสุดของสคริปต์
- **Efficiency ของ Auto+Manual** ใช้เวลาสะสม (สร้างแผนอัตโนมัติ + ปรับแก้) จึงสะท้อนเวลาของกระบวนการทำงานจริงในคลินิก สำหรับผู้ป่วย Straight-pass ค่าทั้งสองจะเท่ากัน

**การจัดระดับผลลัพธ์ (Efficiency Band)**

| ช่วงค่า %Time Efficiency | การจัดระดับ | การตีความ |
|---|---|---|
| < 40% | Below | ยังไม่ถึงช่วงเป้าหมาย |
| 40% – 75% | ✓ Target | อยู่ในช่วงเป้าหมายของการลดเวลา |
| > 75% | Exceeds | ลดเวลาได้เกินช่วงเป้าหมาย (สอดคล้องกับเป้าหมายการลดเวลาร้อยละ 75 ในวัตถุประสงค์หลัก) |

สรุประดับกลุ่ม: ค่าเฉลี่ย, SD, จำนวนผู้ป่วยที่อยู่ในช่วง 40–75% และจำนวนที่มากกว่า 75% แยกตาม Auto และ Auto+Manual

#### รูปแบบการแสดงผล (Visualization)

| องค์ประกอบ | รายละเอียด |
|---|---|
| **Data Table** | เวลาที่ใช้จริง (นาที) ของทั้ง 3 แผน, %Time Efficiency ของ Auto และ Auto+Manual และระดับ Efficiency Band รายผู้ป่วย พร้อมตารางสรุประดับกลุ่ม |
| **Planning Time Bar Chart** | กราฟแท่งจัดกลุ่มเปรียบเทียบระยะเวลาของ 3 แผน แท่ง Auto และ Auto+Manual ที่ลดเวลาได้ในช่วง 40–75% จะมี **ขอบสีเหลืองอำพัน** และมีป้ายกำกับร้อยละที่ลดลง (เช่น ↓72%) |
| **Time Efficiency Bar Chart** | กราฟแท่ง %Time Efficiency โดยไฮไลต์แถบสี (**Target Band**) ระหว่าง 40–75% เป็นพื้นหลัง |
| **Scatter Plot (Correlation)** | กราฟแสดงความสัมพันธ์ระหว่าง **%Pass Rate (แกน Y)** และ **Planning Time (แกน X)** แยกสีและสัญลักษณ์ตามชนิดแผน พร้อมเส้นถดถอยเชิงเส้น (Linear fit) ค่า Pearson's r และ Spearman's ρ พร้อมค่า p เพื่อหาจุดความคุ้มค่า (Sweet spot) ระหว่างคุณภาพและเวลา |

> **การตีความ Scatter Plot** จุดที่อยู่บริเวณมุมซ้ายบน (เวลาน้อย ผ่านเกณฑ์สูง) แสดงถึงความคุ้มค่าสูงสุดของกระบวนการอัตโนมัติ ค่าสหสัมพันธ์คำนวณจากทุกจุดของทุกแผนรวมกัน ซึ่งไม่เป็นอิสระต่อกันอย่างสมบูรณ์ (ผู้ป่วยรายเดียวกันให้ข้อมูลหลายจุด) จึงควรใช้เพื่อการสำรวจแนวโน้มมากกว่าการอนุมานเชิงสถิติ

### Module 3: คะแนนคุณภาพแผนและความสม่ำเสมอ (Plan Quality Score & Consistency)

โมดูลนี้ใช้การให้คะแนนแบบถ่วงน้ำหนัก (Weighted Score) โดยพิจารณาจาก **ร้อยละความต่างเทียบกับ Clinical Goal Criteria ของสถาบัน** (มิใช่เทียบกับแผน Manual) แต่ละแผนจึงถูกประเมินบนมาตรฐานเดียวกันอย่างเป็นอิสระ

#### 3.1 การคำนวณร้อยละความต่าง (Improvement %)

ค่าความต่างเป็นอัตราส่วนที่ไม่มีหน่วย จึงใช้สมการเดียวกันได้กับ cGy, %Volume และ cc โดยกำหนดให้ **ค่าบวก = ดีกว่าเกณฑ์** และ **ค่าลบ = แย่กว่าเกณฑ์**

```
เกณฑ์ชนิด AtMost  (อวัยวะเสี่ยง / จุดร้อน):  Improvement % = (Goal − Achieved) / Goal × 100
เกณฑ์ชนิด AtLeast (ความครอบคลุมเป้าหมาย):   Improvement % = (Achieved − Goal) / Goal × 100
```

**การจำแนกประเภทเกณฑ์**

| ประเภท | เงื่อนไข | สเกลคะแนน | ตัวคูณ |
|---|---|---|---|
| OAR Sparing | ROI ที่ไม่ใช่เป้าหมาย และ `Criteria = AtMost` | ตาราง 3.2 | ตาราง OAR |
| Target Coverage | `Criteria = AtLeast` | ตาราง 3.3 | ตาราง Target |
| Hot-spot Limit | `Criteria = AtMost` บน BODY หรือโครงสร้างเป้าหมาย (PTV/ITV/CTV/GTV) เช่น `D0.0% <= 4815 cGy` | สเกล OAR แต่ **จำกัดคะแนนสูงสุดที่ +1** | ตาราง OAR |

> **เหตุผลของการจำกัดคะแนน Hot-spot** การมีปริมาณรังสีสูงสุดต่ำกว่าเกณฑ์จุดร้อนมาก ๆ ไม่ได้บ่งชี้คุณภาพที่ดีกว่า และอาจสะท้อนภาวะรังสีไม่เพียงพอ (under-dosage) ในเป้าหมาย จึงไม่ควรได้รับคะแนนสูงเทียบเท่าการลดรังสีในอวัยวะเสี่ยง

#### 3.2 กระบวนการวิเคราะห์อวัยวะเสี่ยง (OAR Sparing – High Weight)

| Improvement % | คะแนนฐาน (Base Score) | ระดับ |
|---|---|---|
| > 10% | **+3** | Excellent – ลดโดสได้มากกว่า 10% |
| 5% – 10% | **+2** | Moderate – ลดโดสได้ 5–10% |
| 2% – 5% | **+1** | Minor – ลดโดสได้ 2–5% |
| −2% < x < 2% | **0** | Equivalent – แตกต่างน้อยกว่า 2% |
| −5% ≤ x ≤ −2% | **0** (ปรับได้เป็น −1 หรือ −2) | ช่วงที่โปรโตคอลไม่ได้กำหนด |
| < −5% | **−2** | Penalty – โดสสูงกว่าเป้าหมายมากกว่า 5% |

| Priority | ตัวคูณ (OAR และ Hot-spot) |
|---|---|
| 1 | ×3 |
| 2 | ×2 |
| 3 | ×1 |

#### 3.3 กระบวนการวิเคราะห์รอยโรคเป้าหมาย (Target Coverage – Medium Weight)

| Improvement % | คะแนนฐาน | ความหมาย |
|---|---|---|
| > 2% | **+3** | ครอบคลุมเป้าหมายเพิ่มขึ้นมากกว่า 2% |
| 1% – 2% | **+1.5** | ครอบคลุมเป้าหมายเพิ่มขึ้น 1–2% |
| −1% < x < 1% | **0** | แตกต่างน้อยกว่า 1% |
| ≤ −1% | **−2** | Penalty – ความครอบคลุมลดลงต่ำกว่าเกณฑ์ |

| Priority | ตัวคูณ (Target) |
|---|---|
| 1 | ×5 |
| 2 | ×3 |
| 3 | ×1 |

> **หมายเหตุการตีความเกณฑ์ Penalty** ข้อความเดิมในโปรโตคอลระบุว่า "ครอบคลุมเป้าหมายลดลง < 2%" ซึ่งหากตีความตามตัวอักษรจะทับซ้อนกับช่วง Equivalent แพลตฟอร์มจึงกำหนดให้ **การลดลงตั้งแต่ 1% ขึ้นไป** ได้คะแนน −2 เพื่อให้สเกลต่อเนื่องและครอบคลุมทุกช่วงค่า ผู้วิจัยควรยืนยันการตีความนี้ในโครงร่างการวิจัย

#### 3.4 กรณีพิเศษในการให้คะแนน

| กรณี | กฎ |
|---|---|
| เกณฑ์มีค่าเป้าหมายเป็นศูนย์ เช่น `V4725cGy <= 0.0%` ของ **Bladder และ Rectum** (Priority 1) | **ความหมาย:** ห้ามมีปริมาตรส่วนใดของอวัยวะได้รับรังสีตั้งแต่ 4725 cGy (105% ของ 45 Gy) ขึ้นไป กล่าวคือ จุดร้อน (hot spot) ที่เกิน 105% ต้องไม่ตกอยู่ในอวัยวะเสี่ยงที่ซ้อนทับหรือชิด PTV (แผน 44 Gy ใช้เกณฑ์เดียวกันในรูป `V4650cGy <= 0.0%`) · ประเมินในกลุ่มอวัยวะเสี่ยง (OAR) ตัวคูณ ×3 · **การให้คะแนน (ปรับปรุงล่าสุด):** Achieved = 0 → **+1**; Achieved > 0 → **0** — ดูหมายเหตุด้านล่าง |
| เกณฑ์จุดร้อนในเป้าหมาย เช่น PTV `V4725cGy <= 0.1%` | จำกัดปริมาตรของ PTV ที่ได้รับรังสีเกิน 105% (ความสม่ำเสมอของโดสในเป้าหมาย) จัดเป็น Hot-spot Limit ในข้อมูลนำร่องพบเพียงแผนเดียวและไม่ได้กำหนด Priority จึงไม่ถูกนำมาให้คะแนน |
| `AchievedValue` ว่าง | ไม่ให้คะแนน (Non-scorable) |
| ไม่มี Priority | ไม่ให้คะแนน (ไม่มีตัวคูณรองรับ) |

> **หมายเหตุเวอร์ชัน (v3.0):** กฎการให้คะแนนของเกณฑ์ที่มีค่าเป้าหมายเป็นศูนย์ถูกแก้ไขจากฉบับเดิม (0 / −2) เป็น (+1 / 0) เนื่องจากค่าความต่างสัมพัทธ์เป็นอนันต์ที่ค่าเป้าหมายศูนย์ทำให้บทลงโทษเดิมไม่ได้สัดส่วนกับความรุนแรงทางคลินิก คะแนนสูงสุดที่เป็นไปได้ (Max Base) ของเกณฑ์กลุ่มนี้จึงเปลี่ยนจาก 3 เป็น **1** ในตัวหารของ Quality Index (ดูข้อ 3.5)

#### 3.5 คะแนนรวมและดัชนีคุณภาพ (Total Score & Quality Index)

```
Weighted Score       = Base Score × Priority Multiplier
Total Quality Score  = Σ Weighted Score                        (ต่อผู้ป่วย ต่อแผน)
Maximum Score        = Σ (คะแนนฐานสูงสุดที่เป็นไปได้จริงของเกณฑ์นั้น × Priority Multiplier)
                        (ค่าเริ่มต้น = 3; Hot-spot = 1; เกณฑ์ค่าเป้าหมายศูนย์ = 1;
                         เกณฑ์ Coverage ที่กำหนดเพดานไว้ที่ 100% = 0)
Quality Index (%)    = Total Quality Score / Maximum Score × 100
```

เนื่องจากจำนวนและชนิดของเกณฑ์แตกต่างกันระหว่างผู้ป่วย (เช่น ผู้ป่วยที่มี Nodal SIB มีเกณฑ์มากกว่า) **Quality Index** จึงเป็นตัวชี้วัดที่ปรับมาตรฐานแล้ว เหมาะสำหรับการเปรียบเทียบข้ามผู้ป่วยและการคำนวณ SD ระดับกลุ่ม ขณะที่ Total Score เหมาะสำหรับการเปรียบเทียบระหว่างแผนภายในผู้ป่วยรายเดียวกัน

> **หมายเหตุเวอร์ชัน (v3.0):** ค่าคะแนนฐานสูงสุดของตัวหาร (Maximum Score) ถูกปรับให้สะท้อนเพดานที่เกณฑ์แต่ละประเภททำได้จริง แทนที่จะใช้ค่า 3 คงที่ทุกเกณฑ์ เนื่องจากเกณฑ์บางประเภท (ค่าเป้าหมายศูนย์, Coverage ที่ Achieved สูงสุดคือ 100%) ไม่สามารถทำคะแนนได้ถึง +3 ในทางคณิตศาสตร์ การใช้ตัวหาร 3 คงที่จะลงโทษผู้ป่วยที่มีเกณฑ์ประเภทนี้มากโดยไม่เกี่ยวกับคุณภาพแผน

**Priority Filtering:** แดชบอร์ดอนุญาตให้ผู้วิจัยเลือกกรองการคำนวณ Quality Index เฉพาะ Priority ระดับใดระดับหนึ่งหรือหลายระดับ (เช่น เฉพาะ Priority 1) โดยสูตรจะคำนวณ Σ Weighted Score และ Σ Maximum Score จากเฉพาะเกณฑ์ในกลุ่ม Priority ที่เลือกเท่านั้น หากไม่มีเกณฑ์ที่ผ่านการกรองสำหรับแผนใด ให้แสดงผลเป็น "—" แทน 0% เนื่องจากไม่มีข้อมูลมิใช่คุณภาพต่ำ ตัวเลือก "All Priorities" ให้ผลลัพธ์เดียวกันกับการคำนวณแบบไม่กรอง

#### 3.6 Critical Alert: ความครอบคลุมของ PTV หลัก

หาก **Target Coverage ต่ำกว่า 95%** ระบบจะปรับสถานะเป็น **"FAIL (Unacceptable)"** และแจ้งเตือนด้วยกล่องข้อความสีแดงในแท็บ Summary ทันที การแจ้งเตือนนี้ **ไม่ถูกกรองด้วย Priority Filter** เนื่องจากเป็นการตรวจสอบความปลอดภัยทางคลินิก มิใช่ส่วนหนึ่งของคะแนนถ่วงน้ำหนัก

| ขั้นตอน | รายละเอียด |
|---|---|
| 1. ระบุโครงสร้าง | PTV หลัก (ชื่อมาตรฐาน `PTV` ไม่รวม PTV-N) |
| 2. ระบุเกณฑ์ | เกณฑ์ `VolumeAtDose` ชนิด `AtLeast` ที่ระดับรังสี ≈ 95% ของ Prescription (คลาดเคลื่อนได้ ±1%) เช่น V4275 cGy สำหรับ 45 Gy และ V4180 cGy สำหรับ 44 Gy |
| 3. ระบุ Prescription | จากแบบฟอร์ม หากไม่มีจะอนุมานจากชื่อ PTV (เช่น `PTV45` → 4500 cGy) |
| 4. เกณฑ์สำรอง (Fallback) | หากแผนไม่มีเกณฑ์ V95%Rx ใช้เกณฑ์ PTV ใด ๆ ที่มี `AcceptanceLevel = 95%` และระบุในคอลัมน์ `Basis` ว่าเป็น `fallback` (เช่น `fallback: V100%Rx`) |
| 5. ตัดสิน | Coverage = ค่าต่ำสุดของเกณฑ์ที่เลือก หาก < 95% → **FAIL (Unacceptable)** มิฉะนั้น → OK |

> **ความสำคัญของคอลัมน์ Basis** การแจ้งเตือนที่อ้างอิงเกณฑ์สำรองอาจใช้ระดับรังสีต่างจากนิยามมาตรฐาน (เช่น V100%Rx ซึ่งเข้มงวดกว่า V95%Rx) ผู้วิจัยควรตรวจสอบเทมเพลต Clinical Goals ของสคริปต์ให้มีเกณฑ์ V95%Rx ครบทุกระดับ Prescription

#### 3.7 การวิเคราะห์ความสม่ำเสมอ (Consistency Analysis)

เป้าหมายของโมดูลนี้คือแสดงว่ากลุ่มแผนอัตโนมัติมีค่า SD ต่ำกว่ากลุ่มแผนด้วยมือ ซึ่งบ่งชี้ความสม่ำเสมอสูงของผลลัพธ์ไม่ว่าผู้ป่วยจะมีความซับซ้อนระดับใด

| วิธีการ | รายละเอียด |
|---|---|
| สถิติเชิงพรรณนา | Mean, SD, Median, Min, Max และ CV ของ Quality Index รายชนิดแผน |
| **Pitman–Morgan Test** | ทดสอบความเท่ากันของความแปรปรวนในข้อมูลแบบจับคู่ (ผู้ป่วยรายเดียวกันถูกวางแผนด้วยสองวิธี) โดยมีสมมติฐานหลัก H₀: Var(X) = Var(Y) |
| Variance Ratio | Var(แผนอัตโนมัติ) / Var(Manual) ค่าน้อยกว่า 1 แสดงว่าแผนอัตโนมัติสม่ำเสมอกว่า |
| **Wilcoxon Signed-rank Test** | ทดสอบความแตกต่างของค่ากลางแบบจับคู่ (ใช้ประกอบ) |
| Per-metric SD | SD ของค่า DVH แต่ละตัวชี้วัด (เฉพาะตัวชี้วัดที่มีข้อมูล ≥ 3 ผู้ป่วย) พร้อมนับจำนวนตัวชี้วัดที่ SD ของ Auto < SD ของ Manual |

สมการของ Pitman–Morgan Test สำหรับคู่ข้อมูล X (แผนอัตโนมัติ) และ Y (Manual) จำนวน n คู่

```
r  = Corr(X + Y, X − Y)
t  = r × √(n − 2) / √(1 − r²)          ,  df = n − 2
p  = 2 × P(T > |t|)
```

เหตุผลที่เลือกใช้ Pitman–Morgan แทน Levene's test คือข้อมูลในการศึกษานี้เป็นแบบจับคู่ (paired) ซึ่งละเมิดสมมติฐานความเป็นอิสระของ Levene's test

> **ข้อจำกัดด้านอำนาจการทดสอบ** เมื่อจำนวนผู้ป่วยยังน้อย การทดสอบความแปรปรวนมีอำนาจต่ำ ผลในระยะนำร่องจึงควรรายงานในเชิงพรรณนา (ค่า SD, CV และ Variance Ratio) จนกว่าจะเก็บข้อมูลครบตามขนาดตัวอย่างที่คำนวณไว้
